# Информационно-поисковая система (лабораторная работа 1, вариант 7)

## Цель проекта

Освоить на практике основные принципы реализации информационно-поисковых систем и методы оценки качества их работы.

## Задачи проекта

- принять естественно-языковые документы и выполнить их предварительную обработку;
- построить поисковый образ документа (ПОД) и поисковый образ запроса (ПОЗ) одной и той же структуры;
- реализовать логическую стратегию поиска (вариант 7) с режимами И / ИЛИ;
- ранжировать найденные документы и выдать ссылку, фрагмент текста и слова запроса, которые встретились в документе;
- программно оценить качество поиска по метрикам точности, полноты, F-меры и MAP.

## Вариант 7

| Параметр | Значение |
|---|---|
| Сфера применения | Локальная вычислительная сеть (LAN) |
| Стратегия поиска | Логическая |
| Язык документов и запросов | Английский |

Тестовая коллекция — это набор английских PDF-документов о LAN: обзор сети, Ethernet, топологии, коммутация, адресация, VLAN, беспроводная сеть и безопасность. Документы создаются автоматически при первом запуске в каталоге `data/documents`.

```

```

Пайплайн, который вызывается из `main`:

1. загрузить ресурсы NLTK;
2. при необходимости сформировать PDF-коллекцию по теме LAN;
3. извлечь текст, токенизировать, лемматизировать и добавить документы в базу;
4. пересчитать нормированные векторы документов;
5. выполнить логический поиск и (по команде) посчитать метрики качества и построить график.

## Формулы

Обозначения: $N$ — число документов в базе, $P_i$ и $N_k$ — число документов, содержащих термин $i$ (или $k$), $Q_i^j$ и $N_{dk}$ — частота термина в документе, $D$ — размер словаря.

### Инверсная частота термина

$$
B_i = \log\frac{N}{P_i}
$$

Чем чаще термин встречается в коллекции, тем меньше его $B_i$. Если термин есть во всех документах, $B_i = 0$.

### Вес термина в документе

$$
A_i^j = Q_i^j \cdot B_i
$$

Это произведение частоты термина в документе на его инверсную частоту (схема TF–IDF).

### Нормированный вектор документа

Документу $d$ ставится в соответствие вектор весов

$$
\mathbf{D} = \{w_{d1},\ldots,w_{dD}\},\qquad
w_{dk} = \frac{N_{dk}\cdot\log(N/N_k)}{\sqrt{\sum_t \left(N_{dt}\cdot\log(N/N_t)\right)^2}}.
$$

### Бинарная матрица информационного массива

Документ — двоичный вектор длины $D$: 1, если термин входит в документ, иначе 0. Массив $L$ имеет размерность $N \times D$:

$$
L = \{b_{ij}\},\qquad
b_{ij} =
\begin{cases}
1, & t_j \in l_i, \\
0, & t_j \notin l_i.
\end{cases}
$$

### Линейный отклик системы на запрос

$$
\mathbf{r} = L \times \mathbf{q}
$$

Координата $r_i$ равна числу терминов запроса, найденных в документе $i$.

### Вектор запроса

$$
\mathbf{Q} = \{w_{q1},\ldots,w_{qD}\},\qquad
w_{qj} =
\begin{cases}
1, & \text{термин есть в запросе}, \\
0, & \text{иначе}.
\end{cases}
$$

### Косинусная мера близости

$$
\operatorname{sim}(d,q) = \frac{(\mathbf{D},\mathbf{Q})}{\lVert\mathbf{D}\rVert\,\lVert\mathbf{Q}\rVert}
$$

где $(\mathbf{D},\mathbf{Q})$ — скалярное произведение, $\lVert\cdot\rVert$ — евклидова норма.

### Метрики качества

$$
P = \frac{|\mathrm{Retrieved}\cap\mathrm{Relevant}|}{|\mathrm{Retrieved}|},\qquad
R = \frac{|\mathrm{Retrieved}\cap\mathrm{Relevant}|}{|\mathrm{Relevant}|},\qquad
F_1 = \frac{2PR}{P+R}.
$$

Average Precision для одного запроса:

$$
\mathrm{AP} = \frac{1}{|\mathrm{Relevant}|}\sum_{k=1}^{|\mathrm{Retrieved}|} P@k\cdot \mathrm{rel}(k).
$$

MAP — среднее AP по набору запросов.

## Как работает проект

1. **Предварительная обработка.** Текст PDF приводится к нижнему регистру, пунктуация удаляется, слова токенизируются, английские стоп-слова отбрасываются, остальные лемматизируются WordNet. Так строятся термины словаря.

2. **Индексирование.** Класс `Document` считает частоты терминов $Q_i^j$, обновляет глобальный словарь и счётчики $P_i$. После загрузки всей коллекции пересчитываются нормированные векторы, потому что IDF зависит от $N$.

3. **Логический поиск (вариант 7).** Запрос тоже лемматизируется. Строится бинарный вектор $\mathbf{q}$ и отклик $\mathbf{r}=L\times\mathbf{q}$.
   - режим **ИЛИ** (по умолчанию): документ попадает в выдачу, если $r_i > 0$;
   - режим **И**: документ попадает в выдачу, только если все термины запроса в нём есть; неизвестное системе слово даёт пустую выдачу.

4. **Упорядочение.** Среди документов, прошедших логический фильтр, считается косинус между нормированным вектором документа и бинарным вектором запроса. Выше оказывается документ, в котором термины запроса весомее по TF–IDF.

5. **Выдача.** Для каждого результата показываются идентификатор, заголовок, дата, релевантность, первые 300 символов, список слов запроса, найденных в документе, и путь к файлу (активная ссылка открывается командой `open`).

6. **Оценка качества.** Команда `eval` прогоняет заранее размеченные запросы, печатает таблицу $P$, $R$, $F_1$, AP и MAP и сохраняет столбчатую диаграмму в `data/quality_metrics.png`.

## Запуск

Из каталога `Lab 1`:

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

Из корня репозитория кавычки должны охватывать весь путь (иначе PowerShell передаст в Python только каталог `Lab 1`):

```powershell
python "Lab 1\main.py"
python "Lab 1" --eval
```

Полезные ключи:

```powershell
python main.py --demo --no-interactive
python main.py --query "ethernet switch vlan"
python main.py --query "wireless access point" --and
python main.py --eval
```

В интерактивном режиме доступны `search`, `and`, `list`, `open`, `eval`, `help`, `quit`.

## Используемые библиотеки

- **NLTK** — токенизация `word_tokenize`, стоп-слова английского языка, лемматизатор WordNet;
- **PyMuPDF** — чтение и создание PDF;
- **NumPy** — матрица $L$, произведение $L\times q$, скалярное произведение и евклидова норма;
- **Matplotlib** — столбчатая диаграмма метрик качества ($P$, $R$, $F_1$, AP, MAP).
